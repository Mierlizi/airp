# AIRP 基础检索方法优化

## 方法变化

本阶段不再把目标限定为“压缩一次工具响应”，而是同时优化三个量：

1. **预计总成本**：根据任务是否点名一个符号、是否涉及多个代码对象、是否要求调用链或影响分析，估计普通工具读取次数。只有预计至少需要三次读取，或明确属于关系任务时，才建议使用 AIRP。
2. **证据覆盖**：从任务中提取文件名、限定名、常量名和 snake_case 标识符。sufficient=true 除了要求锚点被交付，还要求这些标识符真实出现在源码证据或锚点中；缺失项会显式返回。
3. **自适应检索宽度**：单一限定符号使用 narrow；多个对象使用 balanced；调用链、依赖与影响任务使用 broad。不再对每个任务固定返回两个锚点。

这形成“任务剖面 → 候选召回 → 动态宽度 → 聚焦代码切片 → 标识符覆盖检查 → 成本路由”的完整路径。所有步骤均为本地确定性算法，不调用额外模型。

## 确定性消融

使用安装态实验中的同一组 12 个真实源码问题，对比旧的固定 balanced 与新的自适应策略。使用本地缓存的 o200k_base 对完整 JSON 工具响应精确计数。

| 指标 | 固定 balanced | 自适应策略 | 变化 |
|---|---:|---:|---:|
| 12 题响应 Token | 7,066 | 5,993 | **−15.19%** |
| 证据充分 | 12/12 | 12/12 | 不变 |
| 使用一个锚点 | 0/12 | 10/12 | +10 |
| 建议调用 AIRP | 强制 12/12 | 0/12 | 避免 12 次无收益调用 |

这 12 题都是约 1,850 行项目中的精确事实问题，普通搜索通常只需一次文件读取。路由器将其全部判定为不值得调用 AIRP，与此前安装态 A/B 得出的经验结论一致。若宿主执行该路由，混合策略在这组任务上的 AIRP 增量开销为零，而不是强制调用时的 +135.43%。

原始结果：[adaptive-retrieval-v15.json](../benchmarks/runs/adaptive-retrieval-v15.json)。

## 验证

- 43 项单元测试全部通过。
- 新测试覆盖单符号窄检索、关系任务宽检索、成本建议和缺失标识符导致 sufficient=false。
- MCP 单入口的自动索引、查询、编辑、验证、测试、提交与错误传播全部通过。
- 消融报告明确只统计本地工具响应，不把它表述为完整 Agent Token。

## 仍未根除的限制

成本路由目前使用规则和实际锚点路径数，没有从大规模真实任务中学习阈值。它能可靠排除明显不适合 AIRP 的简单任务，但尚未证明“建议启用”的大型任务一定获得净收益。

更根本的固定成本来自宿主：自动加载 Skill 会产生额外说明读取轮次。实验中，不读取 Skill 的一次重复已经出现 AIRP 比两次普通读取节省 4.08%，而读取 Skill 的重复仍为负收益。要去掉该成本，需要把 Skill 改成仅显式调用，或提供不含自动 Skill 的 MCP-only 轻量插件配置；这属于插件调用策略变化，不是检索算法内部可以消除的成本。

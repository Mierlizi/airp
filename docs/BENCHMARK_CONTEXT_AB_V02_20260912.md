# AIRP v0.2 Context Compiler 优化实验

日期：2026-09-12

## 结论

在与 v0.1 相同的 3 个代码理解问题、模型和两轮配对方法下，v0.2 的 AIRP 条件与完整文件 Baseline 均为 **6/6 正确**。AIRP 将输入 Token 从 101,094 降至 79,046，减少 **21.81%**；输入与输出合计从 102,426 降至 80,069，减少 **21.83%**。

相较 v0.1 的 16.29% 输入 Token 降幅，新方法提高 **5.52 个百分点**。由于实现文件在优化中发生变化，应比较各版本同轮 Baseline 的降幅，不能直接比较原始 Token 总数。

## 方法变化

- 父类只发送结构轮廓，避免在目标方法之外再次发送完整类体。
- 依赖默认发送签名和定位信息；调用者、测试按 `intent` 选择。
- 只发送目标实际引用的 import。
- `known_hashes` 允许后续调用复用客户端已有符号，不重复传正文。
- `prepare` 把定位、hash 和编辑上下文合为一次调用。
- 成功测试只返回紧凑摘要；失败时才返回诊断日志。
- MCP 接口由 13 个细粒度工具合并为 7 个任务型工具，减少工具定义与选择开销。

## 汇总结果

| 指标 | Baseline | AIRP v0.2 | 变化 |
|---|---:|---:|---:|
| 正确任务 | 6/6 | 6/6 | 持平 |
| 输入 Token | 101,094 | 79,046 | **-21.81%** |
| 非缓存输入 Token | 41,190 | 19,142 | -53.53% |
| 输出 Token | 1,332 | 1,023 | -23.20% |
| 输入+输出 Token | 102,426 | 80,069 | **-21.83%** |
| 提供的上下文字节 | 115,560 | 17,426 | -84.92% |
| 总耗时 | 67.44 秒 | 62.31 秒 | -7.60% |

相同三个目标在 v0.1 AIRP 上下文中每轮合计 10,700 字节，在 v0.2 中为 8,713 字节，进一步减少约 18.6%。最终输入 Token 的降幅小于正文降幅，因为系统提示和运行环境仍有固定上下文。

## 验收与限制

每个问题预设事实要点，原始回答完整保存。确定性检查器最初漏掉“不截断”“跳过放不下”“不会由 `visit_Call` 直接记录”等等义表达；人工按源码核对后只扩充同义词，不修改问题和回答。正式实验应预先冻结结构化验收器。

该实验只测只读上下文选择，没有覆盖 MCP schema 的精确 Token、工具往返、编辑、重试和隐藏测试。Baseline 是完整目标文件；样本仅 3 个自有仓库问题，因此结果是方法验证，不是商业成本承诺。

# AIRP v0.6 综合 Token 实验

本报告将两组彼此独立的实验合并展示，但不相加：语言×规模矩阵测量上下文交付；真实模型配对实验测量模型可观测的输入、推理和输出阶段。

## 语言与规模矩阵

矩阵覆盖 Python、JavaScript、TypeScript、Go、Rust、Java、C#、C、C++、Ruby 和 PHP，以及 10、100、500、1000 文件四档合成仓库。每个文件24个符号。基线为搜索结果加完整目标文件，AIRP为一次 `task_context(response_mode=auto)`。使用 `o200k_base` 统计完整工具响应，且只有正确锚点并恢复答案标记的交点才计入。

44/44交点通过。总平均减少81.28%，每任务平均减少620.84 Token。

## 真实模型阶段实验

为避免发送项目源码，本实验只向模型发送生成的合成代码，并把 Codex 工作目录设为空临时目录。11种语言各取一个规模，覆盖全部四档；每个任务运行 baseline/AIRP 两个条件并重复2次，共22组配对、44次真实模型调用。模型为 `gpt-5.6-luna`、low reasoning。顺序在任务与重复间交错，验收值在运行前冻结，输出必须完整匹配 `<answer>标记</answer>`。

baseline与AIRP均为22/22成功，质量门槛通过。

| 可观测环节 | Baseline | AIRP | 累计减少 | 每组平均减少 | 降幅 |
|---|---:|---:|---:|---:|---:|
| 工具上下文载荷 | 16,712 | 3,108 | 13,604 | 618.4 | 81.40% |
| 模型输入（含固定系统上下文） | 291,276 | 277,672 | 13,604 | 618.4 | 4.67% |
| 未缓存输入（诊断项） | 69,580 | 62,120 | 7,460 | 339.1 | 10.72% |
| 推理输出 | 0 | 0 | 0 | 0 | 不适用 |
| 最终答案输出 | 426 | 426 | 0 | 0 | 0% |
| 模型总Token（输入+输出） | 291,702 | 278,098 | 13,604 | 618.4 | 4.66% |

上下文载荷是模型输入的一部分，未缓存输入也是输入的子集，这些行不能相加。固定系统提示和工具定义约占大量输入，因此81.40%的任务载荷降幅在模型总账单中表现为4.66%。在该精确答案任务中，AIRP没有减少答案或推理Token；它只减少送入模型的代码。

编辑生成、测试执行和失败修复没有可靠数据，综合图明确标为“未测”。AIRP目前只对Python提供受控写入，因此不能将Python编辑结果推广到其余语言。

## 结论边界

这组结果可靠支持以下窄结论：在11种语言的词面明确、单目标、只读代码理解任务中，AIRP保持相同精确答案，并显著减少代码上下文载荷；考虑Codex固定系统上下文后，实际总模型Token降低4.66%。它不证明复杂缺陷修复、跨模块推理、动态行为或多轮编辑也有相同收益。

# V34 大型仓库编辑前沿实验

## 结论

AIRP 已从“精确目标函数注入”升级为有界编辑前沿。对于大型未索引仓库，插件在第一次模型请求前收集目标实现，并在预算内补充声明、同文件直接依赖、相关测试、代表性调用点和验证提示。缺少任何契约证据时，状态会降为 `partial`，不再把“找到函数”误报为“可直接编辑”。

在 4 个固定公开仓库、4 种语言、56,409–532,132 行索引源码的真实编辑任务中，baseline 与 AIRP 均 4/4 通过同一隐藏验证。模型总 Token 从 754,268 降至 465,329，减少 **38.31%**；命令调用从 30 次降至 22 次，减少 **26.67%**；总耗时从 397.50 秒降至 334.80 秒，减少 **15.77%**。

## 方法变化

大型未索引仓库不再立即构建全仓持久图。新的快速路径执行：

1. 从显式调用、限定名或代码样式名称定位定义候选；小写调用形式（如 `slugify(...)`）现在可进入快速路径。
2. 用任务中的目录/模块提示给重名实现排序。
3. 完整保留目标实现。
4. 在剩余预算内依次放入声明、最多 2 个同文件依赖、最多 2 个测试摘录和 1 个调用点摘录。
5. 输出 `edit_frontier` 和 `edit_ready`。没有契约证据时，`status: partial`。
6. 编辑意图优先于提示中的 `caller`/`impact` 字样，避免“修改并检查调用者”被误判为纯影响分析。
7. C/C++ 验证提示使用目标函数和直接被调函数生成隔离 harness 方案，避免默认尝试构建整个大型工程。

引用文件采用目标命中附近的有界行摘录，不解析整棵引用文件 AST。快速路径同时以源文件数和源码字节数触发，覆盖 ripgrep 这类文件较少但源码体积较大的仓库。

## 真实模型结果

固定模型为 `gpt-5.6-luna`、`low` effort。每组从干净副本开始，编辑由隐藏验证器判定。

| 仓库 | 语言 | 规模（行） | 任务 | Baseline Token | AIRP Token | Token变化 | 命令变化 | 结果 |
|---|---:|---:|---|---:|---:|---:|---:|---|
| Django | Python | 532,132 | 扩展 `slugify` 关键字参数并保持默认行为 | 183,972 | 77,568 | **-57.84%** | 10→4 | 双方通过 |
| NestJS | TypeScript | 133,789 | 重构 `isNil` 并保持类型谓词 | 304,485 | 154,005 | **-49.42%** | 8→6 | 双方通过 |
| ripgrep | Rust | 56,409 | 重构 `should_preprocess` 条件表达式 | 135,299 | 101,192 | **-25.21%** | 6→5 | 双方通过 |
| Redis | C | 383,301 | 给 `stringmatchlen` 增加负长度边界 | 130,512 | 132,564 | **+1.57%** | 6→7 | 双方通过 |
| **合计** | 4 种 | — | 4 项 | **754,268** | **465,329** | **-38.31%** | **30→22** | **4/4 vs 4/4** |

Redis 的 AIRP 组定位和修改一次完成，但随后尝试了 `make` 和完整 `gcc` 检查；这些验证因工程/平台依赖失败，使 Token 略增。代码已加入依赖感知的隔离 harness 提示，确定性回归验证了提示内容。受账户模型用量上限影响，改进后的 C 单项模型复测尚未运行，因此不能宣称 C 回归已经消除。

| Django | 2,977 | 20,114,252 | 2.521 s | 2,727 | sufficient |

四项平均注入 2,470 字符，首次本地检索平均 1.213 秒。该开销包含扫描大型未索引仓库，未把全仓图构建时间藏在后台。

## 实验审计

首轮实验发现并修复了两个测量缺陷：

- Django 验证器依赖未安装的 `asgiref`，导致双方正确修改被误判失败。V34 改为隔离执行目标函数，同时检查装饰器未重复。
- 行编辑辅助脚本曾接受空输入并删除目标行。V34 明确拒绝空替换；Redis 验证器也检查相邻公共函数仍存在。

V34 的 Django baseline 与全部 AIRP 运行重新执行；NestJS、ripgrep、Redis baseline 复用同模型、同任务、同源码和同验证条件下的 V33 成功记录。原始事件汇总保存在 `benchmarks/published/large-repo-edit-v34.json`，确定性检索记录保存在 `benchmarks/published/large-edit-frontier-local-v34.json`。

## 适用边界

这 4 项实验支持“精确局部编辑在大型仓库可获得明显综合收益”，不支持对所有大型编辑任务外推 38.31%。跨模块 API 迁移、广泛重命名、生成代码、动态框架绑定和需要完整构建的任务仍可能需要持久图、语言服务器或额外读取。每种语言目前只有一个大型编辑任务，尚未形成语言总体估计；C 的改进验证策略仍需补做模型复测。

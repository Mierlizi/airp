# AIRP v0.6：成本感知上下文

v0.6 解决跨语言矩阵暴露的小文件负收益问题。`task_context` 新增 `full`、`compact` 和 `auto` 三种响应模式。MCP 和 CLI 默认使用 `auto`：保留源码、锚点、receipt、充足性和必要的省略/复用信息，移除选择打分、重复预算字段等审计元数据。`full` 供调试和详细实验使用。

当只有一个读取型锚点、所有已交付符号都在同一文件、没有省略，且完整文件在预算内并比紧凑符号响应更便宜时，`auto` 返回 `full-file-cost-bypass`。编辑、影响分析、多文件证据和存在省略时不使用该旁路。

## 实验

前置的 2 文件、8 符号/文件冒烟矩阵在 v0.5 完整响应下为 -28.03% 到 2.45%。v0.6 `auto` 模式在 11 种语言下为 46.86% 到 57.41%，11/11 正确。

完整矩阵包含 Python、JavaScript、TypeScript、Go、Rust、Java、C#、C、C++、Ruby 和 PHP，每种语言使用 10、100、500 和 1000 文件四档，共 44 个交点。44/44 恢复了正确锚点和答案标记。平均上下文交付 Token 降幅为 81.28%，范围为 77.87%–83.80%。原始数据为 `benchmarks/runs/language-scale-tokens-v06.json`。

该数字是“搜索命中+完整目标文件”与“一次 AIRP auto 响应”的合成上下文交付比较，使用 `o200k_base`。它没有调用模型，不表示完整 Agent 总 Token 减少 81.28%。

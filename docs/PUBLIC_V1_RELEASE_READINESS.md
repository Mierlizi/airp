# AIRP GitHub 公开第一版说明

## 产品类型与使用方式

AIRP 是适用于 Codex、Claude Code、DeepSeek Harness 及 MCP 客户端的本地预模型代码上下文插件。开发者正常用自然语言提出代码问题；`UserPromptSubmit` Hook 在第一次模型请求前读取本地仓库，选出与任务有关的实现、测试和关系证据，再把小型 `<airp-context>` 注入模型上下文。日常使用不需要手动调用 AIRP 工具。

从公开仓库安装：

```shell
git clone YOUR_REPOSITORY_URL airp
cd airp
python scripts/install_local_plugin.py --dry-run
python scripts/install_local_plugin.py
```

要求使用 Python 3.11+ 运行安装脚本。安装脚本会把该解释器的绝对路径写入用户自己的插件副本，因此 Codex 后续不依赖 `python` 命令别名。插件自带 AIRP Python 运行时。仅分析 Python 时不需要额外运行依赖；分析 JavaScript、TypeScript、TSX、Go、Rust、Java、C、C++、C#、Ruby 或 PHP 前，在同一 Python 环境安装：

```shell
python -m pip install "tree-sitter-language-pack>=1.1,<2"
```

安装后打开目标代码仓库并直接提问，例如：

- `解释 QuerySet.get 在多条记录匹配时的行为。`
- `修改 base64_decode，让非 ASCII 输入转换为 BadData，并运行聚焦验证。`
- `分析这个方法的调用者、依赖和受影响测试。`

`status: sufficient` 表示当前证据覆盖了任务中的显式代码标识符；`partial` 时插件不再发送源码正文，只返回原因、有限锚点提示和聚焦补查动作。`index_mode: exact-symbol fast start` 表示只解析了精确命中的文件，适合局部实现问题，不代表已获得全仓调用关系。

## 创新点及边界

AIRP 使用的基础组件主要是成熟开放技术：Python AST、Tree-sitter、SQLite、FTS5、静态调用候选、增量文件指纹和 Codex Hook。公开发布时不应声称发明了这些算法，也没有完成专利级新颖性检索。

当前具有差异化的方法组合是：

1. **预模型证据注入**：在第一次模型请求前本地计算证据，消除常见的“模型判断要搜索 → 工具返回 → 模型再次推理”往返。
2. **双层仓库策略**：精确局部任务使用快速候选扫描和候选文件解析；模糊、调用链和影响任务使用持久完整图。
3. **成功成本路由**：优化目标是完成正确任务所需的总 Token、工具调用和时间，同时用 `sufficient/partial` 阻止证据不足时的虚假节省。
4. **任务感知编辑证明**：把精确编辑位置、相关测试、验证环境、异常保护边界和吞错结构直接编译进证据包。
5. **失败计入实验**：只有基线与 AIRP 都通过评分或隐藏验证，Token 下降才作为有效收益报告。

这些属于架构与工程方法创新。目前没有证据证明其在学术或专利意义上全球首创。与持久代码图、Codebase Memory、语义检索和代码索引 MCP 产品存在明显技术重叠。

V32 各语言的大型精确阅读结果：Python 70.57%、TypeScript 76.76%、Rust 69.23%、C 50.45%。大型仓库首次证据包为 0.50–3.71 秒、616–1,898 字符。

这些数字不能合并成一个“任何代码任务平均节省率”。V32 只有四个精确阅读任务；V26 只有一个编辑任务；V19 的仓库仅有 268–5,054 行生产源码。大型跨模块编辑、动态框架行为、模糊需求和未命中精确符号的任务仍缺少可靠总体数据。

公开、脱敏的机器可读汇总位于 `benchmarks/published/v1_verified_results.json`。包含命令轨迹和本机路径的原始运行记录不进入公开仓库。

## 当前实用性判断

适合公开第一版的场景：已知类、函数或方法名的解释；局部缺陷定位；小范围编辑；寻找少量相关测试；大型仓库首次精确查询。Python 能力最完整。安装 Tree-sitter 后，多语言结构检索和精确实现提取可用。

需要谨慎宣传的场景：全仓影响分析、动态分派、依赖注入、反射、生成代码、跨服务关系、大型重构。非 Python 的跨文件调用图仍有限。快速启动仍线性扫描源码；Django 约 53 万行时为 3.7 秒。

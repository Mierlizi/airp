# AIRP v0.3 普适化改造记录

日期：2026-09-12

v0.3 针对静态关系精度、全量索引、上下文选择、预算误差、缓存一致性和解析失败恢复进行了结构性改造。

## 已落地

- 文件级增量索引：未变化文件直接复用，单文件变化只重新解析该文件。
- SQLite 查询索引：符号、入边、出边和 import 使用独立索引表；影响分析不再对每个节点扫描全部边。
- 结构后端：Python 使用标准 AST；已验证 11 种常用语言通过 Tree-sitter 做只读符号和上下文索引。其他已缓存语言可通过扩展名自动发现。
- 容错恢复：Python 文件出现临时语法错误时保留最后一次成功结构并标记 `analysis_stale`，禁止基于旧结构写入。
- 相关性排序：目标、父级、测试、调用依赖和调用者按角色与引用强度排序，预算优先留给高价值符号。
- 上下文收据：`receipt_id` 保存精确的 `symbol_id -> hash`，避免仅凭相同内容 hash 误复用另一个符号。
- 精确预算：可选 tiktoken 编码器提供真实 Token 硬上限；默认字节模式继续支持任意模型。
- 按需计算：`minimal` 不再执行调用者或受影响测试分析。

## 实测

| 验证 | 结果 |
|---|---:|
| 自动化测试 | 30 passed |
| 多语言矩阵 | 11/11 语言成功，14 个结构符号，含 Java 重载，零诊断 |
| 5,000 文件首次索引 | 15.68 秒 |
| 5,000 文件无变化重建 | 0.76 秒，复用 5,000 文件 |
| 5,000 文件单文件变化 | 0.78 秒，只重解析 1 文件 |
| 5,000 文件上下文查询 | 0.30 秒 |

规模数据来自本地合成项目，记录在 `benchmarks/runs/scale-index-v03-5000-20260912.json`。它衡量索引和查询，不代表真实项目语义精度。

## 仍然存在的边界

普适化分为结构能力和语义能力。v0.3 已普适化结构查询，但没有宣称所有语言都具备编译器级调用关系。Python 关系仍可能受反射和动态分派影响；非 Python 当前没有跨文件关系和受控写入。下一层精度需要接入 Pyright/Jedi、SCIP 或各语言 LSP，并以统一置信度合并结果。

每次工具调用仍枚举受支持文件的大小和时间戳来检测索引是否过期，复杂度为文件数线性；5,000 文件实测可用，但百万文件 monorepo 应接入 Git 变更清单或文件系统 watcher。SQLite 仍为单写者，适合本地单仓库 Agent，而非高并发共享服务。

外部模型 v0.3 A/B 因源码外发审批未获通过而没有运行。Token 收益仍引用 v0.2 的 6/6 配对实验；v0.3 只完成本地 Tokenizer、结构正确性和规模回归，不能伪称新的模型效果数据。

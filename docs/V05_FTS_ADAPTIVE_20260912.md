# AIRP v0.5：索引召回与自适应取证

v0.5 落地“通用验证上下文层”的第一步：不再在每次自然语言查询时把全部符号源码载入 Python。索引阶段将符号名、限定名、路径和源码词项写入 SQLite FTS5；查询先召回有界候选，再使用 AIRP 现有的名称/路径/源码权重重排。无 FTS5 的 SQLite 环境保留原有全量词法回退。

FTS 记录按变更文件更新。删除或重命名文件时删除旧符号，只对新增或变更文件重新分词；旧数据库首次升级会自动建立全量 FTS 数据。

Skill 增加证据升级梯度：先用 narrow 或 balanced 上下文；锚点错误时改用具体词或符号查询；锚点正确但整符号被省略时增加预算；动态分派、反射、生成代码、配置与框架注册则升级到文件、LSP/编译器、运行跟踪和测试。Receipt 只在已发送源码仍留在当前模型上下文时使用。

## 5,000 文件合成基准

在同一本地基准脚本上，v0.4 自然语言任务上下文为 0.454 秒，v0.5 本次运行为 0.348 秒，降低约 23.3%，且都正确选中 `func_4999`。v0.5 首次索引、无变更索引、单文件变更分别为 16.785、0.838、0.853 秒。原始结果位于 `benchmarks/runs/scale-index-v05-5000-20260912.json`。

这是单次合成性能检查，会受文件系统缓存和主机负载影响，不是模型 Token A/B。FTS5 减少本地召回时间；Token 改善仍由整符号预算、去重、receipt 和 Agent 按需升级产生。正式结论应使用质量非劣约束下的配对 Agent 实验。
